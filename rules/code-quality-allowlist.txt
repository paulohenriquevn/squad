# rule-id: SQ-ALW-01
# Code-quality allowlist — explicit exemptions with mandatory sunset.
#
# Authoritative source: rules/code-quality-golden-rule.md § 4 (Allowlist mechanism).
#
# Each ACTIVE entry downgrades a finding by ONE severity level
# (HARD → SOFT_CAP, SOFT_CAP → SOFT_FLOOR). Expired entries (today > SUNSET)
# are IGNORED — the underlying finding re-fires at full severity.
#
# Format (one entry per line) — SIX pipe-separated fields, in this order:
#   ECOSYSTEM | FILE-PATH | FINDING-TYPE | SYMBOL-OR-LINE | REASON | SUNSET (YYYY-MM-DD)
#
# Where:
#   ECOSYSTEM     — the language, as `load_allowlist` validates it (python, typescript, rust, go).
#   FILE-PATH     — path within the project where the finding fires (e.g., src/legacy/foo.py).
#   FINDING-TYPE  — one of: dead_code | symbol_fab | orphan_export | mutation_low | architecture.
#                   These are the DETECTOR families (D1..D5), NOT the stable identifiers from
#                   `code-quality-golden-rule.md § 2`.
#   SYMBOL-OR-LINE— the symbol name the finding names, or the line number.
#   REASON        — free-form justification.
#   SUNSET        — ISO date. MUST be ≤ 90 days from entry. Past it, the finding re-fires at full
#                   severity and the entry is reported as expired.
#
# Lines starting with `#` and blank lines are skipped.
#
# #343 — this header used to document a FOUR-field format
# (`IDENTIFIER | FILE:LINE | SUNSET | RATIONALE`) that `load_allowlist` has never accepted. Writing
# an entry the way the file itself described raised `ValueError`, which the orchestrator turns into
# an `allowlist_malformed_entry` HARD finding — so following the documentation produced a WORSE
# outcome (FAIL_HARD, cap 49) than adding nothing at all. The parser is the source of truth here
# because it is the thing that runs; the prose is what was wrong.
# Whitespace around `|` is tolerated.
#
# Adding/modifying entries:
#   - REQUIRES CHANGELOG entry under `[Unreleased] § Changed`.
#   - REQUIRES ADR for HARD-level exemptions (`records/adrs/`).
#
# A malformed entry triggers the `allowlist_malformed_entry` HARD finding and
# aborts allowlist processing for the current run.
#
# Empty allowlist is the default. Add entries only when the underlying issue
# cannot be fixed within the iteration AND the risk is documented.

# Example (commented) — SIX fields, in the order the parser reads them:
# python | src/legacy/migrator.py | dead_code | migrate_v09 | legacy migration helper retained for the v0.9 rollback path; remove after v1.0 | 2026-11-30
#
# This example carried the FOUR-field shape until 2026-09-21 — the very shape the note
# above records as one `load_allowlist` has never accepted. #343 corrected the header
# and left the example, so the obvious way to write a first entry (copy the example)
# produced `allowlist_malformed_entry`: HARD, and it aborts allowlist processing for the
# whole run. `tests/test_the_allowlist_example_is_one_the_parser_accepts.py` now parses
# every example under this marker.
