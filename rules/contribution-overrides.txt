# THIS PROJECT's contribution conventions, overriding the kit's defaults.

# `rules/contribution-conventions.md` is the kit's contract and a reinstall overwrites
# it. This file is yours: it ships empty, a reinstall preserves it, and
# `check_contribution_conventions.py` reads it before applying any default.
#
# Format:  key = value        (one per line; `#` comments; unknown keys are refused)
#
# Keys:
#   commit_types    = comma-separated. REPLACES the kit's set
#   commit_scopes   = comma-separated. When set, a scope outside it is refused
#   subject_max     = integer. Default 85 — DERIVED from this repository's own
#                  history, not from the 72 convention. See the sixteen lines of
#                  reasoning at check_contribution_conventions.py:64. This line read
#                  72 while the gate applied 85, so a project setting 72 to match the
#                  'default' was tightening it without meaning to.
#   body_required   = comma-separated types. Default: feat,fix

# and applies to nothing is worse than an absent one: the project believes it
# declared something.

# TWO THINGS CANNOT BE OVERRIDDEN and an attempt is refused rather than ignored:

#   crediting a tool misattributes the accountability authorship carries

#   the secrets rule for issues — no token, cookie, password or customer data in an
#   issue body, ever
#

# and without adding a capability. `change(phases): DISCOVER is conditional, and the

# exist and `refactor` promises behaviour did not move, which is the opposite of what
