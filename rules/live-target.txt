# O kit distribuía aqui o alvo vivo do ecossistema em que foi escrito — uma URL de
# ambiente dev e dois domínios concretos. Num outro projeto isso é pior que
# vazio: `/discover-execute (live-test mode)` e `/acceptance` sondariam o produto de outra pessoa e
# chamariam o resultado de evidência deste projeto. Declare o alvo DESTE sistema.

# Where /discover-execute (live-test mode) exercises the ecosystem — PER-PROJECT, edit this.
#
# This is the DEV environment the Squad probes to produce runtime evidence. It is
# deliberately NOT the same declaration as `acceptance-target.txt`:
#
#   acceptance-target.txt  → the RELEASED delivery, exercised by /acceptance to
#                            decide whether a shipped thing actually works.
#   live-target.txt (here) → the DEV environment, probed by /discover-execute in
#                            live-test mode to find things worth fixing.
#
# Collapsing them would point /acceptance at dev and let a milestone be declared
# validated against an environment nobody ships. Keep them separate.
#
# Format: `key = value`, one per line. `#` starts a comment. Blocks are per-domain;
# a domain with no block has no live surface, and /discover-execute (live-test mode)
# REFUSES on it rather than inventing one.
#
# domain      (required) a domain registered in the routing table (rules/cycle-backlog.md)
# kind        (required) one of: web | api | cli | cluster
# target      (required) how to reach it — URL, endpoint, or command
# auth        (optional) NAME of the credential needed. NEVER the value. If a run
#             needs one and it is absent, ASK THE HUMAN — do not skip the probe,
#             do not fabricate the observation, do not record a finding as if the
#             surface had been exercised.
# notes       (optional) anything a prober must know before touching it
#
# Example of one block, to be replaced by yours:
#
#   domain = frontend
#   kind = web
#   target = https://app-dev.example.internal
#   notes = Verified reachable YYYY-MM-DD: HTTP 200, no redirect. Probe with the
#           real browser via chrome-devtools MCP. Non-destructive discipline
#           applies — do not disturb personal tabs or sessions.
#
# --- this ecosystem -------------------------------------------------------



# A domain with NO block here is refused by /discover-execute in live-test mode, by
# design. Use --mode review, bug, or evolve on it instead.
#
# That absence is a statement, not an omission: a library, a database extension and
# an infrastructure module have no running surface a browser can probe. Declaring a
# block for one of them because "live-test sounds thorough" produces theatre, not
# evidence. If such a component later gets a deployed endpoint worth probing, add
# its block then — and only then.
