# The review panel — who judges a DISCOVER opportunity and a PLAN plan
#
# WHY THIS FILE EXISTS
# --------------------
# Decided 2026-09-08, reworked 2026-09-09. Both phases produce a document that no
# script can judge: `discover-confidence` and `plan-confidence` are deterministic and
# score STRUCTURE — pointers resolve, the shape is complete, the contract is
# satisfied. What they cannot ask is whether the evidence that resolves actually
# SUPPORTS the conclusion drawn from it. That is the judgement a panel is for.
#
# Three reviewers, 2 of 3 to advance. Below the majority the document returns as
# NEEDS_REVISION, a verdict that already exists and already holds an item.
#
# THE REVIEWERS ARE THE PROJECT'S OWN SPECIALISTS
# -----------------------------------------------
# Until 2026-09-09 a row named a MODEL and a lens ("evidence-lens | claude-opus-5").
# That described how a reviewer would be reached and never said WHO was reviewing, so
# nothing could check that the reviewer had any standing to judge the document in
# front of it — and nothing convened them (issue #65).
#
# A row now names an AGENT that must exist in the project the kit is running in.
# `agents/README.md` already gives every specialist a single thing it decides, and
# both gated phases fall squarely inside one of those specialities:
#
#   DISCOVER asks whether evidence supports a conclusion. That is verbatim what
#   `nemesis-claim-auditor` decides — "whether a claim this system made about itself
#   is supported by what it measured" — and what `leonardo-researcher` supplies from
#   the other side, closing the gap between what a decision needs to know and what
#   anyone actually read.
#
#   PLAN asks whether the shape proposed is the right one and grounded on disk. That
#   is `vera-technical-arbiter`, which "refuses a verdict it cannot ground in
#   something on disk", with `nemesis-claim-auditor` auditing the plan's claims.
#
# `daedalus-tech-lead` is deliberately absent from both: it takes an item from idea
# to release PR, so on a gated item it is the AUTHOR, and an author never sits on the
# panel judging their own document.
#
# WHY THE PANEL IS STILL THE PROJECT'S TO CONFIGURE
# -------------------------------------------------
# This is a `.txt` under `rules/`, which is the layer the installer PRESERVES
# (`rules/README.md`: the question that places a file is not who reads it, it is who
# owns it). Which specialists a project has, which models it can reach and what they
# cost it are not the kit's business — the kit owns the RULE that a majority is
# needed, that the panel must not be one family, and that a seat naming an agent the
# project does not have is an unconvened panel rather than a passing one.
#
# THE ONE CONSTRAINT THE KIT DOES IMPOSE
# --------------------------------------
# At least one counted vote must come from a recognised family outside the one the
# kit itself runs on. Three Claudes asked three times share their failure modes: a
# plausible fabrication that survives one tends to survive its siblings, which is the
# single thing an orthogonal reviewer is there to catch. Correlated approval is not
# independent approval, and a panel that cannot tell the difference is a signature
# ceremony with extra latency.
#
# An UNRECOGNISED model supplies neither side. Otherwise `--model anything` would
# prove orthogonality by typing.
#
# WHAT AN ABSENT REVIEWER MEANS
# -----------------------------
# It does NOT mean the document was rejected. Two approvals out of two is not 2-of-3:
# the threshold is over a full panel, so a missing reviewer is an abstention, and an
# abstention approves nothing and rejects nothing. The panel did not convene, the item
# returns to the registry with an `access` impediment (`halt_disposition.py`), and the
# queue takes the next item.
#
# That is why `check_panel_capability.py` asks the question AT INTAKE instead:
# discovering per-item that the panel cannot be formed costs the run, exactly as
# `check_merge_autonomy.py` argues about branch protection.
#
# FORMAT
# ------
#   reviewer = <phase> | <agent> | <model> | <how to invoke>
#
# <phase>   one of `panel_phases` below. Rows are phase-scoped because the
#           speciality that qualifies a reviewer for DISCOVER does not qualify it
#           for PLAN, and a single roster hid that.
# <agent>   the sub-agent to convene. A `builtin` agent must exist as
#           `agents/<agent>.md` in the running project; `convene_panel.py` refuses a
#           seat it cannot resolve rather than quietly seating nobody.
# <model>   the model that agent runs on, which is what the diversity rule reads.
# <invoke>  `builtin` for a sub-agent of this session, or an executable on PATH.
#
# The lens each reviewer applies belongs in its own agent file; this table answers
# only WHO sits on the panel, on what, and whether they can be reached.
#
# A LIMIT THAT WAS STATED, AND THEN CLOSED
# ----------------------------------------
# This file recorded on 2026-09-09 that a `judge-codex:*` seat could only be verified by
# finding the `codex` CLI on PATH — which proves the CLI is installed and NOT that the
# judge-codex plugin is — and that closing it "means asking Claude Code which plugins are
# installed, which nothing in this kit does yet".
#
# That was true of the kit and false of the machine. Claude Code keeps
# `~/.claude/plugins/installed_plugins.json`, every entry carries an `installPath`, and
# `mechanisms/conventions/installed_plugins.py` now reads it. A `plugin:agent` seat is
# verified like every other one: the plugin must be installed AND supply that agent.
#
# The closure matters more than the hole did. A project's largest pool of specialists is
# the one its plugins supply — measured here, 152 agents across 17 loop plugins against
# 14 in the kit — and that was exactly the pool the panel had been accepting on the
# strength of a name.
#
# What remains open: an executable seat is still only verified as a binary on PATH. That
# is the right check for a seat that IS a binary; it is a weaker one for a seat that is a
# plugin reached through a binary, so prefer naming the agent.

reviewer = discover | nemesis-claim-auditor      | claude-opus-5   | builtin
reviewer = discover | leonardo-researcher        | claude-sonnet-5 | builtin
reviewer = discover | argus-pattern-analyst    | claude-opus-5   | builtin

reviewer = plan     | vera-technical-arbiter     | claude-opus-5   | builtin
reviewer = plan     | nemesis-claim-auditor      | claude-sonnet-5 | builtin
reviewer = plan     | argus-pattern-analyst      | claude-opus-5   | builtin

# The phases a panel gates. A phase not listed here advances on its own verdict.
# CODE-QUALITY and RELEASE are deliberately absent: both already derive their
# verdict from a script, and a panel voting on a decision already made
# deterministically adds cost and no information.
reviewer = design   | vera-technical-arbiter     | claude-opus-5   | builtin
reviewer = design   | nemesis-claim-auditor      | claude-sonnet-5 | builtin
reviewer = design   | argus-pattern-analyst      | claude-opus-5   | builtin

# THIS PROJECT waives the cross-family requirement, and says what that costs.
#
# The kit's rule stands and the argument above stands with it: three Claudes asked three
# times share their failure modes, and a plausible fabrication that survives one tends to
# survive its siblings. Nothing here disputes that. The honest options were two — run no
# panel, or run one and say what it is worth. This is the second.
#
# WHY, MEASURED 2026-09-21 — AND NOT "NO PROVIDER IS CONFIGURED"
# --------------------------------------------------------------
# This reason read "no non-Anthropic provider is configured for this project" until
# 2026-09-21, and that was false on this machine in three separate ways:
#
#   codex CLI 0.120.0 is on PATH at /usr/bin/codex
#   ~/.codex/auth.json exists — the account is authenticated
#   judge-codex v0.1.0 is installed and supplies discover-judge, plan-judge, final-judge
#
# So the seat LOOKED fillable, and `cycle-discover.md` and `cycle-plan.md` both name
# `judge-codex:*` as the orthogonal chair. What stops it is one version behind the CLI:
#
#   $ codex exec --model gpt-5-codex …
#   400 invalid_request_error: The 'gpt-5-codex' model is not supported when using
#                              Codex with a ChatGPT plan
#   $ codex exec …                       # account default
#   400 invalid_request_error: The 'gpt-5.5' model requires a newer version of Codex.
#                              Please upgrade to the latest app or CLI
#
# Every model this account exposes is refused by this CLI. npm publishes 0.155.1; the
# installed build is 0.120.0, and it is a root-owned global install.
#
# THIS IS THE FAILURE THE CAPABILITY GATE ALREADY RECORDED. `check_panel_capability.py`
# probes with `shutil.which` and says so in its own output: "a seat whose CLI resolves
# and whose model is unavailable reads as reachable here and terminates when dispatched
# — measured on a consumer 2026-09-16". Declaring the seat on the strength of the binary
# would have reproduced that, spending two sibling seats before the third terminated.
#
# TO REMOVE THE WAIVER, in this order — do not skip the third step:
#   1. sudo npm install -g @openai/codex@latest     # 0.120.0 -> 0.155.1+
#   2. codex exec "Reply with exactly: SEAT_OK"     # must PRINT SEAT_OK, not 400
#   3. swap one `argus-pattern-analyst` row per phase for the judge-codex seat, e.g.
#        reviewer = plan | judge-codex:plan-judge | gpt-5.5 | builtin
#      with the model spelled as the one step 2 actually answered on — `review_panel`
#      derives the family from that string by prefix (`gpt` -> openai), so a stale
#      spelling buys the family label without the reviewer behind it.
#   4. delete both keys below.
#
# Until then `argus-pattern-analyst` holds the orthogonal chair, and it is orthogonal by
# LENS rather than by family — less than the rule asks for, and more than nothing.
single_family_panel = accepted
single_family_reason = codex CLI 0.120.0 is installed and authenticated but refuses every model this account exposes (400: gpt-5.5 requires a newer CLI); measured 2026-09-21, see the block above for the upgrade path

panel_phases = discover, plan, design
